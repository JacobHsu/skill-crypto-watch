## A-1 Multi-Time Period 多時間框架

`mtp` · Score · trend · 1.0

**看什麼**：圖表上方的彩色方塊，代表較高級別最近幾根 K 棒是綠還是紅。較高級別的對應在 `profile.toml [timeframes.htf]`：15m→4h、1h→1d、4h→1w、1d→1M。

```mermaid
flowchart TD
    s["取較高級別最近 11 根 K<br/>（含正在形成的那根）"] --> r["綠 K 比例 = 綠 ÷ 11"]
    r --> q{"比例"}
    q -- "≥ 60%" --> p["+1"]
    q -- "≤ 40%" --> n["-1"]
    q -- "40% 到 60%" --> z["0"]
    s -. "沒有較高級別資料" .-> u["未核對"]
```

**設計決策**
- **包含正在形成的較高級別 K 棒**：圖上的方塊就是這樣畫的，而且 1w 的一根要等一週才收盤，排除它會讓訊號落後太多。回放時仍然會截斷。
- **11 根、60%**：對應圖上方塊的數量；60% 和 check.html 的多數門檻一致。
- 只看顏色（收 ＞ 開），不看漲跌幅。圖上方塊也只有顏色。

**參數**：`count = 11`、`majority = 0.6`

## A-2 Williams Fractals 威廉碎形

`fractals` · Choice · structure · 1.0

**看什麼**：△（上碎形，局部高點）和 ▽（下碎形，局部低點）有沒有被收盤突破。

```mermaid
flowchart TD
    s["找最近一個 △ 和最近一個 ▽"] --> b1["△ 之後第一根收盤高於 △ 的 K 棒"]
    s --> b2["▽ 之後第一根收盤低於 ▽ 的 K 棒"]
    b1 --> q{"哪個突破<br/>發生得比較晚？"}
    b2 --> q
    q -- "向上突破較晚（或只有它）" --> up["choice = up<br/>+1"]
    q -- "向下跌破較晚（或只有它）" --> dn["choice = down<br/>-1"]
    q -- "都沒有突破" --> no["choice = none<br/>0"]
    s -. "沒有已確認的碎形" .-> u["未核對"]
```

**設計決策**
- **碎形本身不是訊號，被突破才是**。這是 Bill Williams 的原意，也是 check.html 的描述。
- **以「較晚發生的突破」為準**：兩邊都被突破時，最新的方向代表目前狀態。
- **碎形需要右側 2 根確認**（`fractals.periods = 2`），所以最新的碎形最少是 2 根前的。左側允許最多 4 根等高 K 棒，和 TradingView 的畫法一致。
- 型別是 Choice，因為 A-4 組合項需要知道 `up` / `down` 狀態本身。

## A-3 Williams Alligator 威廉鱷魚

`alligator` · Choice · trend · 1.0

**看什麼**：三條平滑移動平均（藍 jaw 13/8、紅 teeth 8/5、綠 lips 5/3，以 hl2 為來源並往右位移）的排列和張口大小。

```mermaid
flowchart TD
    s["計算開口 = 三線最大距離 ÷ ATR"] --> q1{"開口 ＜ 0.3 ATR？"}
    q1 -- "是" --> sl["sleeping 睡覺<br/>0"]
    q1 -- "否" --> q2{"綠 ＞ 紅 ＞ 藍<br/>且收盤在綠線上方？"}
    q2 -- "是" --> up["up 張口向上<br/>+1"]
    q2 -- "否" --> q3{"藍 ＞ 紅 ＞ 綠<br/>且收盤在綠線下方？"}
    q3 -- "是" --> dn["down 張口向下<br/>-1"]
    q3 -- "否" --> mx["mixed<br/>0"]
```

**設計決策**
- **「睡覺」用 ATR 正規化的開口判斷**：直接用價差的話，BTC 和小幣的門檻會差好幾個數量級。除以 ATR 讓同一個門檻適用所有幣種和級別。
- **要求收盤在綠線外側**：三線排好但價格已經回到線內，代表「張口」正在收合，不算。
- 四種狀態分開保留，因為 A-4 需要區分「睡覺」和「方向不明」。

**參數**：`min_spread_atr = 0.3`

## A-4 ↳ Alligator × Fractal 鱷魚確認碎形

`alligator_x_fractal` · Score · trend · 1.0 · **組合項**

**看什麼**：A-3 和 A-2 的答案。這是 Section A 唯一會給 ±2 的項目。

```mermaid
flowchart TD
    s["讀 alligator.choice<br/>和 fractals.state"] --> q1{"鱷魚 up<br/>且碎形 up？"}
    q1 -- "是" --> p2["+2 強力訊號"]
    q1 -- "否" --> q2{"鱷魚 down<br/>且碎形 down？"}
    q2 -- "是" --> n2["-2 強力訊號"]
    q2 -- "否" --> q3{"鱷魚 sleeping？"}
    q3 -- "是" --> z1["0：碎形訊號無效"]
    q3 -- "否" --> z2["0：方向不一致或未確認"]
    s -. "任一方未核對" .-> u["未核對"]
```

**設計決策**
- **±2 是刻意的**：Bill Williams 的交易系統中，「鱷魚張口 + 碎形突破」是主要進場訊號，check.html 標記為強力訊號。
- **鱷魚睡覺時碎形無效**：這是原始系統的規則，盤整中的碎形突破多半是假突破。
- 只有兩者都同向才給分；單邊成立已經在 A-2、A-3 各自投過票了。

## A-6 Bollinger Bands 布林通道

`bb` · Score · channel · 1.0（B-10 `bb_b` 同規則）

```mermaid
flowchart TD
    s["BB(20, 2)<br/>帶寬 vs 3 根前"] --> q1{"最高價 ≥ 上軌<br/>且收盤 ≥ 中軌？"}
    q1 -- "是" --> e1{"帶寬擴大？"}
    e1 -- "是" --> p["+1 觸上軌且張開"]
    e1 -- "否" --> z1["0 觸上軌但收窄<br/>注意假突破"]
    q1 -- "否" --> q2{"最低價 ≤ 下軌<br/>且收盤 ≤ 中軌？"}
    q2 -- "是" --> e2{"帶寬擴大？"}
    e2 -- "是" --> n["-1 觸下軌且張開"]
    e2 -- "否" --> z2["0 觸下軌但收窄<br/>可能反彈"]
    q2 -- "否" --> z3["0 在軌道內游走"]
```

**設計決策**
- **「觸碰」用最高 / 最低價，不用收盤**：圖上看到的「碰到上軌」是影線碰到。
- **同時要求收盤在中軌同側**：避免長上影線、收在中軌下方的 K 棒被當成強勢。
- **帶寬必須擴大才算**：通道收窄時碰軌，往往是區間震盪的邊緣，順勢解讀會出錯。這是 check.html 的「觸上軌 + 開口」條件。
- 布林在這裡是**順勢**解讀（沿上軌走 = 強），不是均值回歸。

**參數**：`width_lookback = 3`

## A-8 BB / KC Squeeze 擠壓

`squeeze` · Choice · volatility · 1.0

```mermaid
flowchart TD
    s["比較 BB 與 KC"] --> q1{"BB 完全落在 KC 內？"}
    q1 -- "是" --> on["on：Squeeze ON 蓄勢<br/>0（noul = 1）"]
    q1 -- "否" --> q2{"收盤位置"}
    q2 -- "高於 KC 上軌" --> up["off_up<br/>+1"]
    q2 -- "低於 KC 下軌" --> dn["off_down<br/>-1"]
    q2 -- "KC 內" --> off["off：已釋放但未突破<br/>0"]
```

**設計決策**
- **擠壓中不給方向**：擠壓只說「快要動了」，沒說往哪動。
- **釋放後要突破 KC 才給方向**：BB 走出 KC 只代表波動放大，價格真的走出 KC 才是方向確認。
- 節點同時輸出 `noul`（擠壓中 = 1），但目前沒有 gate 使用它（見 [03 已知取捨](03-decision-model.md#已知取捨)）。
- 群組是 volatility，不受趨勢 gate 影響。

## A-13 Donchian Channels 唐奇安通道

`donchian` · Score · channel · 1.0

```mermaid
flowchart TD
    s["前一根 K 棒的 20 根通道上下軌"] --> q{"本根收盤"}
    q -- "高於前根上軌（創 20 根新高）" --> p["+1"]
```

## A-15 Zig Zag 折線

`zigzag` · Choice · structure · 1.0

```mermaid
flowchart TD
    s["轉折點：深度 10、偏差 5%"] --> c{"至少 2 高 2 低？"}
    c -- "否" --> u["未核對<br/>波動未達偏差門檻"]
    c -- "是" --> q{"比較最近兩個高點<br/>和最近兩個低點"}
    q -- "高點遞升且低點遞升" --> p["ascending<br/>+1"]
    q -- "高點遞降且低點遞降" --> n["descending<br/>-1"]
    q -- "其他" --> m["mixed<br/>0"]
```

**設計決策**
- **高低點都要同向**才算趨勢結構（道氏理論的 HH + HL）。只有一邊成立視為整理。
- **轉折點不足時回傳未核對，而不是 0**：1h 上 5% 的偏差很少形成擺盪，這時「沒有結構」是因為參數不適合這個級別，不是市場中性。這正是「我不知道」和「中性」的區分。
- **已知限制**：最後一個轉折點會隨新 K 棒改變（重繪），兩點比較也很粗糙。這是設定檔裡附上 [Jev 範例](08-config-and-calibration.md#jev-節點)的原因。

**參數**：`[indicators] zigzag = { deviation = 5.0, depth = 10 }`

## A-17 Linear Regression 線性迴歸

`linreg` · Score · trend · 1.0

```mermaid
flowchart TD
    s["最近 100 根最小平方迴歸"] --> sl["整段累計斜率 %<br/>= 每根斜率 × 100 ÷ 收盤"]
    s --> nr["距離 = 收盤與迴歸值的差 ÷ 殘差標準差"]
    sl --> f{"累計斜率<br/>未達 ±2%？"}
    f -- "是：近乎水平" --> z1["0"]
    f -- "否" --> q{"方向與位置"}
    nr --> q
    q -- "線上方、不貼線、斜率向上" --> p["+1"]
    q -- "線下方、不貼線、斜率向下" --> n["-1"]
    q -- "其他（含貼線 0.5σ 內）" --> z2["0"]
```

**設計決策**
- **斜率換算成整段累計百分比**：原始斜率（每根多少美元）無法跨幣種比較。
- **「貼線」用殘差標準差衡量**：價格在迴歸線 0.5σ 內代表還在通道中心，沒有方向優勢。
- 要求「位置」和「斜率」同向：價格在上升趨勢線下方，可能是趨勢正在轉弱。

**參數**：`flat_pct = 2.0`、`near_dev = 0.5`；長度 `[indicators] linreg = { length = 100 }`

- **讀迴歸線的斜率，不讀 A-17 的分數**：A-17 還要求價格不貼線，但這裡只問「短期（SAR）和中期（100 根趨勢）方向是否一致」，所以只取斜率。
